# ARCLIO

> **Learn. Build. Become.**
>
> منصة تعليم تقني عالمية تعتمد على بناء المشاريع الحقيقية **Project-Based Learning**، مصممة لسد الفجوة بين الأساسيات البرمجية للمبتدئين وبين العمل الهندسي الاحترافي في سوق العمل.

---

## مرحبًا بك في مستودع مشروع ARCLIO (Master Repository)

أهلاً بك في فريق **ARCLIO**! سواء كنت بتكتب أول زرار في HTML أو بتتعلم إزاي تنظم كود JavaScript وتعمل Responsive Design، المستودع ده معمول لغرضين أساسيين في نفس الوقت:

1. **منتج برمجي حقيقي (Real Software Product)**: منصة تعليمية حديثة، سريعة، ومتجاوبة مع كل الشاشات، مبنية لمجتمع المطورين عالميًا.
2. **بيئة تعلم حقيقية (Real Learning Environment)**: مساحة عمل تدريبية منظمة لفريقنا (10–15 مطور)، هنتطور فيها مع بعض من خلال كتابة الكود، مراجعة الكود **Code Review**، حل المشاكل، وإطلاق ميزات حقيقية خطوة بخطوة.

## 🎯 فلسفة المنتج (Product Philosophy)

أغلب الكورسات التقليدية بتوقع المطور المبتدئ في "فخ الشروحات" **Tutorial Trap**: تفضل تتفرج على فيديوهات لساعات طويلة، لكن أول ما تفتح ملف كود فاضي تلاقي نفسك مش عارف تبدأ منين.

في ARCLIO بنعتمد على دورة تعلم نشطة من 5 مراحل:

```text
┌──────────┐     ┌──────────┐     ┌─────────┐     ┌──────────┐     ┌─────────┐
│  Learn   │ ──> │ Practice │ ──> │  Build  │ ──> │  Review  │ ──> │ Become  │
│  تعلّم   │     │  تدرّب   │     │  ابنِ   │     │  راجع    │     │  أصبح   │
└──────────┘     └──────────┘     └─────────┘     └──────────┘     └─────────┘
```

- **تعلّم (Learn)**: دروس مركزة تشرح المفهوم البرمجي وليه بنستخدمه **(Why it exists)** قبل ما نكتب كود.
- **تدرّب (Practice)**: تحديات برمجية صغيرة **Micro-Challenges** لتثبيت المنطق وطريقة كتابة الكود **Syntax**.
- **ابنِ (Build)**: مشاريع حقيقية ومكونات برمجية **Components** بمتطلبات واقعية وتصميم حقيقي.
- **راجع (Review)**: مراجعة الكود بين الزملاء **Peer Review** لنتعلم كتابة كود نظيف ومنظم.
- **أصبح (Become)**: تصبح مطورًا قادرًا على بناء تطبيقات كاملة مع سيرة ذاتية حقيقية **Portfolio**.

## 🚀 دورة عمل المطور (Developer Workflow)

كل مهمة **Task** في ARCLIO بتمر بخطوات واضحة ومحددة:

```text
قائد الفريق يحدد لك المهمة (TASK-XXX)
                  │
                  ▼
افتح ملف المهمة في مجلد `/tasks/` واقرأه كويس جدًا
                  │
                  ▼
راجع المتطلبات السابقة (Prerequisites) والأدلة في `/guides/`
                  │
                  ▼
اسحب أحدث كود من الفرع الرئيسي (Pull Latest Changes):
  git checkout main
  git pull origin main
                  │
                  ▼
أنشئ فرع جديد خاص بالمهمة (Create Branch):
  git checkout -b feat/task-xxx-description
                  │
                  ▼
اكتب الكود المطلوب في `/src/`
(التزم بمعايير الكود المكتوبة وممنوع تعديل ملفات خارج نطاق المهمة)
                  │
                  ▼
راجع شغلك واختبره يدويًا (Manual Testing)
(اختبر على الموبايل والتابلت والديسكتوب وتأكد من الـ Accessibility)
                  │
                  ▼
احفظ التغييرات برسالة واضحة (Conventional Commit):
  git commit -m "feat: add course card component"
                  │
                  ▼
ارفع الفرع وافتح طلب دمج (Open Pull Request):
  git push -u origin feat/task-xxx-description
                  │
                  ▼
مراجعة الكود من زملائك وقائد الفريق (Code Review)
(ناقش الملاحظات واعمل التعديلات المطلوبة)
                  │
                  ▼
الموافقة والدمج في الفرع الرئيسي (Approve & Merge)
                  │
                  ▼
🎉 المهمة اكتملت (Done)! وثق اللي اتعلمته في `/learning/`
```

## 🌿 قواعد التعامل مع Git والفروع (Branching Rules)

علشان نضمن إن الكود دايمًا نظيف ومن غير أي تعارضات **Merge Conflicts** بين الـ 10–15 مطور:

1. **ممنوع نهائيًا العمل مباشرة على فرع `main`**. فرع `main` محمي ودايمًا جاهز للاستخدام.
2. **تسمية الفروع (Branch Naming)**:
   - `feat/task-XXX-short-name` (إضافة ميزة جديدة أو مكون UI)
   - `fix/task-XXX-short-name` (إصلاح خطأ برمجي أو مشكلة في التصميم)
   - `refactor/task-XXX-short-name` (تحسين وتنظيم الكود دون تغيير الوظيفة)
   - `docs/task-XXX-short-name` (تحديث التوثيق والأدلة)
   - `test/task-XXX-short-name` (إضافة اختبارات وتحقق من الجودة)
3. **رسائل الحفظ (Commit Messages)**:
   - `feat: add responsive navigation drawer`
   - `fix: correct color contrast on secondary button`
   - `docs: update git workflow guide`
   - `refactor: extract color tokens into tokens.css`

👉 *اقرأ [دليل Git](guides/GIT-GUIDE.md)، [دليل الفروع](guides/BRANCHING.md)، و[دليل رسائل الحفظ](guides/COMMITS.md) قبل البدء.*

## 📋 متى تعتبر المهمة منتهية؟ (Definition of Done - DoD)

المهمة **مش بتعتبر منتهية** بمجرد إن الكود "شغال على جهازي". المهمة بتعتبر **Done** لما:

- [ ] يتم تنفيذ جميع المتطلبات ومعايير القبول **Acceptance Criteria** الموجودة في ملف التاسك.
- [ ] عدم تعديل أي ملفات خارج نطاق المهمة (الالتزام بقاعدة **Do Not Touch**).
- [ ] استخدام عناصر HTML دلالية **Semantic HTML** (العناوين بالترتيب، الأزرار للأكشن، الروابط للتنقل).
- [ ] فحص التصميم المتجاوب **Responsive Design** على الموبايل (375px)، التابلت (768px)، والديسكتوب (1200px+).
- [ ] التأكد من إمكانية الوصول **Accessibility** (التنقل بالكيبورد والتباين اللوني المناسب).
- [ ] عدم وجود أي أخطاء في الـ Console في المتصفح.
- [ ] فتح طلب دمج **Pull Request** باستخدام النموذج الموحد `.github/pull_request_template.md`.
- [ ] الحصول على مراجعة زميل **Peer Review** وموافقة قائد الفريق **Lead Approval**.
- [ ] حل جميع التعليقات والملاحظات بنجاح ودمج الكود في `main`.

👉 *اقرأ الدليل الكامل لـ [تعريف الانتهاء (Definition of Done)](docs/10-DEFINITION-OF-DONE.md).*

## 🛡️ ثقافة مراجعة الكود (Code Review Culture)

مراجعة الكود في ARCLIO هي **فرصة للتعلم وتبادل الخبرات** وليست تصيدًا للأخطاء:

- **للمُراجِع (Reviewer)**: خليك دائمًا لطيف ومحدد، واشرح **ليه** بتقترح تعديل معين. امدح الأفكار الممتازة وساعد زميلك يفهم أفضل الممارسات البرمجية.
- **لصاحب الكود (Author)**: تذكر إن الملاحظات على الكود مش عليك شخصيًا. لو في اقتراح مش فاهمه، اسأل واستفسر علشان تتعلم.

👉 *اقرأ [دليل مراجعة الكود](guides/CODE-REVIEW.md).*

## 🤖 سياسة استخدام الذكاء الاصطناعي (AI Collaboration Policy)

أدوات الذكاء الاصطناعي (زي ChatGPT, Gemini, Copilot) هي أدوات مساعدة ممتازة في التعلم لما نستخدمها بوعي:

- ✅ **استخدام مسموح ومشجع**: تسأل الذكاء الاصطناعي يشرح لك خاصية CSS، يساعدك تفهم رسالة خطأ في الـ Console، أو يقترح عليك فكرة منطقية.
- ❌ **استخدام ممنوع**: تنسخ نص المهمة بالكامل للذكاء الاصطناعي وتنسخ الكود الناتج من غير ما تفهمه وتفتح بيه PR.
- 💡 **القاعدة الذهبية**: لو مش قادر تشرح كل سطر في طلب الدمج بتاعك بالكلمات البسيطة لقائد الفريق، يبقى الكود ده مش جاهز للدمج.

👉 *اقرأ [دليل استخدام الذكاء الاصطناعي في التعلم](guides/AI-ASSISTANCE-GUIDE.md).*

## 📦 البداية السريعة (Quick Start)

1. **انسخ المستودع لجهازك (Clone)**:
   ```bash
   git clone https://github.com/your-org/arclio.git
   cd arclio
   ```
2. **افتح المشروع في المتصفح**:
   - افتح ملف `src/index.html` في المتصفح المفضل لديك (أو استخدم إضافة VS Code Live Server).
3. **اختر مهمتك**:
   - ادخل على [جدول المهام (Tasks Matrix)](tasks/README.md) وشوف رقم مهمتك `TASK-XXX`.
   - افتح ملف المهمة في `/tasks/` واقرأ الشرح والمتطلبات بعناية.
   - أنشئ فرع جديد وابدأ الشغل!
