# 10 — معايير تعريف الانتهاء (Definition of Done - DoD)

في ARCLIO، **تعريف الانتهاء** هو الميثاق الهندسي الملزم بين المطور وفريقه لضمان جودة الكود المرفوع للمنصة.

---

## 🎯 قائمة التحقق العامة لإنهاء المهام (Global DoD Checklist)

قبل الموافقة على أي طلب دمج **Pull Request** ودمجه في فرع `main`، يجب استيفاء المعايير التالية:

### 1. الاكتمال الوظيفي (Functional Completeness)
- [ ] تنفيذ جميع المتطلبات المذكورة في ملف المهمة `TASK-XXX.md`.
- [ ] استيفاء كافة معايير القبول **Acceptance Criteria** بنجاح.
- [ ] معالجة الحالات الخاصة **Edge Cases** (مثل النصوص الطويلة، غياب البيانات، أو بطء التحميل).

### 2. الالتزام بنطاق المهمة (Scope Boundaries)
- [ ] عدم تعديل أي ملفات خارج النطاق المحدد (الالتزام الصارم بقاعدة **Do Not Touch**).
- [ ] حذف أي أكواد تجريبية مؤقتة، أو جمل `console.log` غير ضرورية، أو تعليقات معطلة.

### 3. معايير ونظافة الكود (Code Standards & Architecture)
- [ ] استخدام عناصر HTML دلالية **Semantic HTML** (العناوين متسلسلة `h1` ثم `h2`، الأزرار `<button>` للأكشن، والروابط `<a>` للتنقل).
- [ ] استخدام متغيرات CSS Tokens لجميع الألوان والمسافات والخطوط (ممنوع استخدام ألوان hex عشوائية أو أرقام سحرية).
- [ ] كتابة كود JavaScript نظيف: أسماء متغيرات واضحة، دوال صغيرة ومحددة، ومنع تسريب المتغيرات العامة **Global Scope**.

### 4. فحص التجاوب عبر الشاشات (Responsive Verification)
- [ ] اختبار العرض على الموبايل (عرض 375px / 414px).
- [ ] اختبار العرض على التابلت (عرض 768px).
- [ ] اختبار العرض على الديسكتوب (عرض 1200px+).
- [ ] عدم وجود أي تمرير أفقي غير مقصود **Horizontal Overflow**.

### 5. سهولة الوصول والتنقل (Accessibility Baseline — WCAG 2.1 AA)
- [ ] إمكانية الوصول والتفاعل مع جميع العناصر عبر لوحة المفاتيح (`Tab`, `Enter`, `Space`, `Escape`).
- [ ] ظهور إطار التركيز البصري **Focus Outline** بوضوح لمستخدمي الكيبورد.
- [ ] تحقيق تباين لوني لا يقل عن 4.5:1 للنصوص العادية مقابل الخلفية.
- [ ] وجود وسوم `<label>` لجميع حقول الإدخال، وسمات `aria-hidden="true"` للأيقونات التجميلية.

### 6. جودة طلب الدمج والمراجعة (PR & Review Quality)
- [ ] اسم الفرع مطابق للمعايير (`feat/task-xxx-...`, `fix/task-xxx-...`).
- [ ] رسائل الـ Commit تتبع أسلوب Conventional Commits.
- [ ] ملء كافة خانات نموذج الـ PR مع إرفاق لقطات الشاشة وملاحظات الاختبار اليدوي.
- [ ] الحصول على مراجعة زميل **Peer Review** وموافقة قائد الفريق **Lead Approval**.
- [ ] الرد على جميع الملاحظات وحلها بالكامل.
