# 09 — خارطة الطريق المعمارية للبيانات والحالة (Architecture Roadmap)

المستند ده بيشرح التطور التدريجي في إدارة البيانات **Data Persistence** وإدارة الحالة **State Management** عبر مراحل المشروع الـ 21.

---

## 📈 تطور تدفق البيانات عبر المراحل (Data Flow Evolution)

```text
المراحل 00–04: الهيكل الدلالي الثابت (Static Semantic Markup)
├── بناء هيكل الصفحة بـ HTML5
└── تنسيق الواجهة بمتغيرات CSS Tokens

المراحل 05–09: الذاكرة المؤقتة والتخزين المحلي (In-Memory & LocalStorage)
├── مصفوفات وكائنات برمجية داخل JavaScript (`projectsData`)
├── دوال بناء الـ DOM ديناميكيًا (`renderProjectGrid()`)
└── حفظ التفضيلات محليًا (`localStorage.getItem('arclio_favorites')`)

المرحلة 10: طبقة الخدمات غير المتزامنة (Async Service Layer)
├── ملفات بيانات JSON ثابتة (`/data/projects.json`, `/data/paths.json`)
├── طبقة استدعاء البيانات المركزية (`src/services/api.js`)
└── مخزن الحالة المعتمد على نمط النشر والاشتراك (`src/store/state.js`)

المراحل 11–14: المعمارية الكاملة المنفصلة (Decoupled Full-Stack)
├── واجهة React مع خطافات مخصصة Custom Hooks وإدارة حالة بـ Zustand
├── واجهة برمجة تطبيقات REST API كاملة مع التحقق عبر Zod
└── قاعدة بيانات PostgreSQL مع إدارة المخططات عبر Prisma ORM

المراحل 15–20: منصة الإنتاج المباشرة (Production Real-Time Platform)
├── اتصالات WebSockets / SSE للإشعارات الفورية بملاحظات المراجعة
├── اختبارات شاملة للنظام بالكامل عبر Playwright E2E
└── أتمتة خطوط النشر السحابي المستمر CI/CD
```

---

## 🔒 قواعد وحدود إدارة الحالة (State Boundaries)

1. **حالة الواجهة المحلية (Local UI State)**: تظل محصورة داخل المكون نفسه (مثل: هل القائمة مفتوحة أم مغلقة، أو التبويب النشط حاليًا).
2. **تفضيلات المستخدم المحفوظة**: تُحفظ في `localStorage` مع استخدام بادئة مميزة (مثل: `arclio_theme`, `arclio_favorites`).
3. **البيانات الحقيقية للمنصة**: في المراحل المتقدمة، تكون قاعدة البيانات الخلفية هي المصدر الوحيد المعتمد لحساب تقدم الطالب وتسليم المشاريع والأوسمة.
