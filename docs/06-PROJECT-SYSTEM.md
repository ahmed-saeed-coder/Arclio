# 06 — نظام المشاريع والتقييم (Project System)

نظام المشاريع هو القلب النابض لمنصة ARCLIO، وهو مصمم ليحاكي تذاكر العمل ومواصفات المشاريع الحقيقية في كبرى شركات التقنية.

---

## 🎯 مستويات صعوبة المشاريع (Project Complexity Tiers)

يتم تصنيف المشاريع في ARCLIO إلى 4 مستويات متدرجة:

| المستوى (Tier) | نطاق العمل النموذجي (Scope) | التقنيات المستخدمة | أمثلة عملية للمشاريع |
| :--- | :--- | :--- | :--- |
| **المستوى 1: مبتدئ (Beginner)** | مكوّن UI واحد أو أداة تفاعلية بسيطة | HTML5, CSS Flexbox/Grid, Basic DOM | بطاقة أسعار متجاوبة، نافذة منبثقة Modal، مدير إشارات مرجعية |
| **المستوى 2: متوسط (Intermediate)** | تطبيق متعدد الصفحات يعتمد على الحالة وتخزين البيانات | Vanilla JS, Fetch API, LocalStorage | مستكشف حسابات GitHub، لوحة مهام Kanban، اختبار تفاعلي Quiz |
| **المستوى 3: متقدم (Advanced)** | تطبيق SPA متكامل مع التوجيه وإدارة الحالة العامة | TypeScript, React, Global State | محرر Markdown تعاوني، متجر إلكتروني مصغر مع سلة تسوق |
| **المستوى 4: احترافي (Professional)** | تطبيق سحابي شامل مع واجهة خلفية وقاعدة بيانات | React, Node.js, PostgreSQL, Auth | لوحة تحكم SaaS متعددة المستأجرين، استنساخ معماري لمنصة ARCLIO |

---

## 📋 تشريح ملف مواصفات المشروع (The Project Brief Anatomy)

يحتوي ملف مواصفات كل مشروع على العناصر القياسية التالية:

1. **نظرة عامة على المنتج (Product Overview)**: المشكلة الواقعية وقصة المستخدم وراء فكرة المشروع.
2. **قصص المستخدمين (User Stories)**: عبارات وظيفية دقيقة (مثال: *"بصفتي مستخدمًا، أريد تصفية المشاريع حسب مستوى الصعوبة لأصل للتحدي المناسب لي"*).
3. **المتطلبات التقنية (Technical Constraints)**:
   - القيود المحددة (مثال: الالتزام بـ Semantic HTML، وعدم استخدام مكتبات CSS خارجية في المستوى الأول).
   - مخططات البيانات المتوقعة ونقاط الـ API.
4. **مواصفات التصميم ومصادر Figma**: تصاميم دقيقة لنسخ الموبايل والتابلت والديسكتوب مع رموز الألوان والمسافات.
5. **معايير القبول ومصفوفة الاختبار (Acceptance Criteria)**: سيناريوهات الاستخدام، الحالات الخاصة **Edge Cases**، وفحص إمكانية الوصول.
6. **معايير التقييم التفصيلية (Rubric Scoring Guide)**: أربعة محاور تقييم رئيسية تُقيّم من 1 إلى 4 درجات:
   - *جودة ونظافة الكود (Code Cleanliness)*
   - *صحة الهيكل الدلالي وإمكانية الوصول (Semantic & Accessibility)*
   - *التجاوب مع الشاشات (Responsive Behavior)*
   - *الأداء ومعالجة الأخطاء (Performance & Error Handling)*

```text
┌─────────────────┐
│ اختيار المشروع  │ ──> قراءة المواصفات، مراجعة تصاميم Figma، والتأكد من المتطلبات السابقة
└────────┬────────┘
         ▼
┌─────────────────┐
│ التطوير المحلي  │ ──> العمل عبر فروع Git، كتابة الكود، وإجراء الفحص اليدوي
└────────┬────────┘
         ▼
┌─────────────────┐
│ تسليم المشروع   │ ──> إرسال رابط مستودع GitHub ورابط المعاينة الحية Deployed URL
└────────┬────────┘
         ▼
┌─────────────────┐
│ الفحص الآلي     │ ──> تشغيل أدوات الفحص التلقائي (Axe Accessibility, HTML Linter, Build Check)
└────────┬────────┘
         ▼
┌─────────────────┐
│ مراجعة الأقران  │ ──> تقييم المشروع بواسطة الزملاء والموجهين عبر الـ Rubric وتقديم ملاحظات تعليمية
└────────┬────────┘
         ▼
┌─────────────────┐
│ الإضافة للملف   │ ──> إضافة المشروع المعتمد رسميًا لمعرض أعمال الطالب الشخصي Portfolio
└─────────────────┘
```
