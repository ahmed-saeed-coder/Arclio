# دليل Git للمطورين المبتدئين (Git Guide)

برنامج Git هو نظام للتحكم في الإصدارات **Version Control System**، وظيفته تتبع التغييرات في الكود عبر الوقت والسماح لفرق العمل بالتعاون بدون ما يمسحوا شغل بعض.

---

## 🧠 النموذج الذهني: مساحات Git الثلاث (The Three Git Areas)

```text
┌────────────────────────┐      ┌────────────────────────┐      ┌────────────────────────┐
│ مساحة العمل الفعلية    │ ──>  │ مساحة التجهيز والتحضير │ ──>  │ المستودع المحلي        │
│   Working Directory    │      │     Staging Area       │      │   Local Repository     │
│ (الملفات اللي بتعدلها) │      │ (الكود الجاهز للحفظ)   │      │ (سجل الحفظ الدائم)     │
└────────────────────────┘      └────────────────────────┘      └────────────────────────┘
          │                                  │                                  │
          └─── git add <file> ───────────────┘                                  │
                                             └─── git commit -m "..." ──────────┘
```

---

## 🛠️ أوامر Git الأساسية خطوة بخطوة

### 1. معرفة حالة الملفات (Check Status)
قبل ما تعمل أي حاجة، اعرف إنت واقف على فرع إيه، وإيه الملفات اللي اتعدلت:
```bash
git status
```

### 2. التبديل للفرع الرئيسي وسحب أحدث كود (Pull Latest Changes)
قبل ما تبدأ أي تاسك جديد، لازم تتأكد إن نسختك هي أحدث نسخة من المشروع:
```bash
git checkout main
git pull origin main
```

### 3. إنشاء فرع جديد للمهمة والانتقال إليه (Create Branch)
الأمر `-b` بينشئ الفرع ويحولك عليه فورًا:
```bash
git checkout -b feat/task-014-base-buttons
```

### 4. تجهيز ملفات محددة للحفظ (Stage Files)
جهّز فقط الملفات الخاصة بمهمتك (بلاش تستخدم `git add .` عشوائيًا):
```bash
git add src/styles/components/button.css
```

### 5. حفظ التغييرات برسالة واضحة (Commit Changes)
الـ Commit بياخد لقطة **Snapshot** من الملفات اللي في مرحلة الـ Staging:
```bash
git commit -m "feat: add primary and secondary button components"
```

### 6. رفع الفرع على GitHub (Push to Remote)
الأمر `-u` بيربط فرعك المحلي بالفرع على السيرفر في أول مرة ترفع فيها:
```bash
git push -u origin feat/task-014-base-buttons
```

## ⚠️ أشهر الأخطاء وإزاي تتصرف فيها (Troubleshooting)

- **الخطأ**: كتبت كود بالخطأ على فرع `main` قبل ما تعمل فرع جديد.
  - *الحل*: طالما لسه ما عملتش `commit`، اكتب ببساطة: `git checkout -b feat/your-task-name` وهياخد التعديلات معاك على الفرع الجديد.
- **الخطأ**: ضفت ملفات مش تابعة للتاسك في الـ Staging.
  - *الحل*: استخدم `git restore --staged <filename>` علشان ترجعه من منطقة التحضير.
- **الخطأ**: حصل تعارض **Merge Conflict** أثناء الدمج.
  - *الحل*: متقلقش! افتح الملف المتعارض في VS Code، شوف علامات `<<<<<<< HEAD`، اختار الكود الصحيح، احفظ الملف، واعمل `git add` و `git commit`.
