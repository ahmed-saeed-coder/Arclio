# دليل دورة العمل على GitHub (GitHub Workflow)

المستند ده بيشرح إزاي فريقنا (10–15 مطور) بينسق الشغل على منصة GitHub باستخدام لوحة المهام **Project Board**، المشاكل **Issues**، وطلبات الدمج **Pull Requests**.

---

## 📌 مراحل لوحة مهام الفريق (Kanban Board Stages)

كل مهمة **Task** بتتحرك عبر الأعمدة التالية:

```text
┌─────────┐   ┌───────┐   ┌─────────────┐   ┌────────┐   ┌──────┐   ┌──────┐
│ Backlog │──>│ Ready │──>│ In Progress │──>│ Review │──>│  QA  │──>│ Done │
└─────────┘   └───────┘   └─────────────┘   └────────┘   └──────┘   └──────┘
```

1. **المهام المؤجلة (Backlog)**: مهام مدرجة في الخطة للمراحل القادمة.
2. **جاهزة للبدء (Ready)**: مهام اكتملت جميع متطلباتها السابقة **Prerequisites** وجاهزة لأي مطور يستلمها.
3. **قيد التنفيذ (In Progress)**: مطور أنشأ فرعًا خاصًا ويعمل عليها حاليًا.
4. **تحت المراجعة (Review)**: تم فتح طلب دمج **Pull Request** وفي انتظار مراجعة الزملاء وقائد الفريق.
5. **فحص الجودة (QA)**: فحص مظهر وتجاوب الصفحة على الموبايل والتابلت والديسكتوب والتأكد من عدم وجود أخطاء في الـ Console.
6. **مكتملة (Done)**: تم دمج الـ PR داخل فرع `main` وحذف الفرع الفرعي بنجاح.

---

## 🏷️ ربط المهام بالتذاكر وطلبات الدمج (Linking Issues & PRs)

- لما تستلم مهمة (مثل `TASK-023`)، اطلب من قائد الفريق أو انقل الكارت لخانة **In Progress** وعيّن نفسك مسؤولاً عنه.
- لما تفتح طلب الدمج **Pull Request**، اكتب في الوصف:
  ```text
  Closes #23
  ```
  أو:
  ```text
  Resolves TASK-023
  ```
  منصة GitHub هتقفل التذكرة بشكل تلقائي أول ما الـ PR يتقبل ويتم دمجه.
